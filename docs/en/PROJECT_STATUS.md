# Project Status

This document is the quick project map for teammates. It is meant to be read before the narrower reference docs, and it summarizes implementation scope, folder ownership, forecast-line generation, LLM status, models, backtesting, and suggested next work in one place.

## One-Line Summary

The project has been reorganized from an oil-only dashboard into a universal market forecasting platform. The FastAPI backend, `market_ai` domain logic, Vite frontend, CLI scripts, and model artifacts are separated. The chart displays yfinance market data and forecast quantile paths generated by price time-series models in a TradingView Lightweight Charts-style UI.

The LLM is not used for numeric forecasting. It is only prepared as an interface for explanation and structured event context through `/api/explanation`; by default the system uses a deterministic explanation path.

## Runtime Flow

Use this command to run the local dashboard.

```bash
.venv/bin/python -m uvicorn backend.app.main:app --reload --port 8000
```

Then open this URL.

```text
http://127.0.0.1:8000
```

When the server starts, the backend renders `frontend/index.html` at `/` and mounts `frontend/src` under `/static`. The chart page then calls the API and renders the returned data.

## Data Flow

1. The user selects a symbol and interval in the frontend.
2. The frontend calls `/api/forecast?symbol=...&interval=...` first.
3. The backend route calls `market_ai.forecasting.service.build_forecast()`.
4. `build_forecast()` loads OHLC data through the yfinance provider.
5. The system records whether the data is real, stale, fallback, mock, or error in `data_status`.
6. The forecasting service computes model paths and quantile bands.
7. The API response includes candles, forecast quantiles, scenarios, regime, warnings, and model metadata.
8. The frontend renders the p50 center line plus p10-p90 and p05-p95 bands.

In production, failed live data fetches must not silently fall back to mock data. Mock/fallback data is allowed only when `APP_ENV=development` or `ALLOW_MOCK_DATA=true`.

## How The Chart Forecast Line Is Produced

The current chart center forecast line is `ForecastResponse.forecast[].p50`. It is produced as follows.

1. The system fetches recent OHLC close prices from yfinance.
2. Close prices are transformed into log returns.
3. Multiple forecasting paths are computed.
4. The default primary model is `motif`. If historical motif analogue matching is available, the `motif` path is used; otherwise the system falls back to the `pattern_mlp` path.
5. Forecast paths are cumulative log returns.
6. Prices are reconstructed with `current_price * exp(predicted_cumulative_log_return_h)`.
7. The residual band from the `pattern_mlp` artifact is used to build p05, p10, p25, p50, p75, p90, and p95 quantiles.
8. The band is treated as an unvalidated probabilistic band until coverage is fully measured.

From the frontend perspective, when `/api/forecast` succeeds it renders p50, p10, p90, p05, p95, and bull/base/bear scenario overlays. If `/api/forecast` fails and `/api/chart` fallback is used, the chart compatibility payload may show motif, ensemble, pattern_mlp, cycle, lstm, tcn, drift, flat, and baseline overlays through `forecast_models`.

## Current Model Types

The following logical models are implemented.

| Model | Description | Used in |
| --- | --- | --- |
| `motif` | Compares the recent return window with historical windows and averages similar future paths | Current primary forecast candidate |
| `pattern_mlp` | Global MLP stored as a `.npz` artifact. It predicts volatility-scaled cumulative return paths from pattern features | Motif fallback, ensemble, band calculation |
| `cycle` | Estimates dominant recent return frequency with FFT and extrapolates the cycle | Comparison/ensemble |
| `lstm` | Live cached sequence LSTM path model trained briefly on request data | Comparison overlay, backtest |
| `tcn` | Live cached temporal CNN path model trained briefly on request data | Comparison overlay, backtest |
| `ensemble` | Weighted combination of motif, cycle, and pattern_mlp | Comparison overlay, backtest |
| `flat` | No-change baseline | Baseline |
| `drift` | Recent average return drift baseline | Baseline |
| `random_walk` | No-drift random walk baseline | Baseline |
| `seasonal_naive` | Repeats recent interval-specific seasonal return pattern | Baseline |
| `volatility_scaled_naive` | Uses recent volatility and momentum direction | Baseline |
| `simple_moving_average_path` | Gradually converges toward an SMA target | Baseline |
| `regime_ensemble` | Regime-aware baseline mixture | Added comparison line in chart compatibility payload |

The repository currently has interval-specific `pattern_mlp` artifacts.

| --- | --- | ---: | ---: | --- |

| `1h` | `global_dl_1h_h72.npz` | 96 | 72 | volatility-scaled cumulative returns |

## Is The LLM Running?

The LLM is currently not running as a numeric price forecaster. By policy, the LLM may only be used as a context/event encoder, not as a numeric price model.

Current code behavior:

- The default is `ENABLE_LLM_CONTEXT=false`.
- With that default, `/api/explanation` uses `NullLLMEventEncoder` and deterministic explanation.
- If `ENABLE_LLM_CONTEXT=true` in development without an API key, `MockLLMEventEncoder` produces structured context only.
- Even when an API key exists, `OpenAICompatibleLLMEventEncoder` is currently an interface placeholder and does not make an external LLM call.
- LLM output does not overwrite the forecast price path.

Therefore, the current dashboard forecast line comes from price time-series models and baselines, not from an LLM.

## Backtesting

The backtest entrypoint is:

```bash
.venv/bin/python scripts/backtest/run_backtest.py --symbol CL=F --interval 1d --max-origins 5 --models random_walk,drift,flat --no-plots
```

Backtesting currently uses a walk-forward rolling origin design.

1. Download close series from yfinance.
2. Select the interval horizon, for example `1d=45`, `1h=72`, `30m=120`, `15m=192`.
3. Select multiple origins.
4. At each origin, use only close prices available up to that point.
5. Selected models predict a cumulative log return path for the horizon.
6. Compare the prediction with the future close path.
7. Write point metrics, horizon metrics, probabilistic metrics, regime breakdown, and leaderboard CSVs.

Main metrics include MAE, RMSE, SMAPE, MASE, median absolute error, directional accuracy, pinball loss, p10-p90 coverage, p05-p95 coverage, and Winkler score. Coverage is recorded as a measured metric, but the dashboard band should not be described as fully validated until calibration is repeated across broader assets and periods.

## Implemented

- FastAPI routes are split under `backend/app/api/routes`.
- Domain logic has moved into the `market_ai` package.
- `/api/chart` backward compatibility is preserved.
- New `/api/forecast` contract is available.
- Data status is surfaced as real, stale, fallback, mock, or error.
- Mock/fallback data policy is covered by settings and tests.
- yfinance market data provider is implemented.
- Symbol normalization and interval normalization are implemented.
- Forecast target remains volatility-scaled cumulative log returns.
- Interval-specific global `.npz` artifacts and metadata sidecars are separated.
- Motif, pattern_mlp, cycle, live LSTM/TCN, ensemble, and baseline forecasts are implemented.
- Chart frontend displays p50 line, quantile band, scenario overlay, data status badge, regime badge, and explanation panel.
- Backtest CLI and major metric CSV outputs are implemented.
- Korean/English documentation structure and documentation hygiene checks exist.

## Current Limitations

- External LLM calls are not implemented yet; the adapter is still a placeholder.
- Forecast band calibration is not fully validated.
- `pattern_mlp` metadata is still marked `legacy_npz_v1`, and data hash, git commit, train_start, and train_end are empty.
- Live LSTM/TCN models are trained briefly from request data and cached, so they are not production-grade pretrained registry models.
- Cross-asset features exist behind a setting flag but are disabled by default.
- The frontend is still mostly vanilla JS rather than fully split into components.
- The system still depends heavily on yfinance, so provider abstraction and cache/storage need more work.
- The dashboard has limited UX for exploring backtest results.

## Recommended Next Work

The best next sequence is:

1. Strengthen forecast evaluation and band calibration. Run rolling backtests across multiple symbols, intervals, and periods, then connect coverage, pinball, and interval width to model metadata.
2. Clean up the model registry. Fill artifact version, train period, data hash, git commit, and supported asset class, and distinguish deployable models from experimental models in `/api/models`.
3. Implement the real LLM context encoder adapter. Keep the output schema limited to event scores and structured context, and keep guardrail tests that prevent numeric forecast generation.
4. Expand the data provider layer. Add providers beyond yfinance, local cache, stale rules, and clearer provider error reporting.
5. Split the frontend into components. Separate chart, controls, status badges, model panel, and explanation panel so UI changes are safer for teammates.
6. Connect backtest results to docs and dashboard. Showing the latest leaderboard and regime performance from `outputs/backtests` would make model selection more transparent.
7. Improve operations docs. Link local run, train, backtest, smoke test, and troubleshooting into one onboarding path.
